# KR Appliance Signals

한국 가전 시장에서 삼성전자와 중국 가전 브랜드의 전략을 **사실 기록**으로 추적한다. 고정 질문을 주기적으로 다시 조사하고, 결과를 4유형 기록(지표·사건·해석·전망)으로 저장한 뒤, 그 기록에서 아티클과 Diff(이전 대비 변화)를 만든다. 추측·가설 중심 리포트가 아니라 영업 전략, 판촉 이벤트(정기/비정기), 마케팅, 제품 특장점을 출처와 함께 시간순으로 쌓는 것이 목적이다.

## 주제와 질문

| 카테고리 | 폴더 | 질문 |
|---|---|---|
| 1. Samsung Korea Appliances | [`samsung/`](samsung/) | S1~S7 |
| 2. China Brands in Korea | [`china-brands/`](china-brands/) | C1~C6(브랜드별, 재조사 중) |
| 3. Korea Market Facts | [`market/`](market/) | X1 시장 조건·성과, X2 규제·정책, X3 경쟁 구도 전환, X4 선택 조건 |

질문 전문과 추적 지표는 각 카테고리 README, 질문별 `request_r1.md`에 있다. 질문 번호 규칙: `S1~` · `C1~` · `X1~` · 기록 `<질문>-M/E/I/F-001` · 추적 지표 `<질문>-T1~`.

중국 브랜드 대상: 브랜드마다 질문 하나(C1 로보락, C2 드리미, C3 에코백스, C4 샤오미, C5 TCL, C6 하이센스·마이디어·하이얼·모바). 각 질문은 조직·제품·채널·AS·신뢰·판촉·마케팅·성과 6개 축을 진입·확장·정착·주도 4단계로 판정한다. 2026-10-21 C1 완료, C2~C6은 같은 방식으로 차례로 재조사한다.

## 운영 원칙

- **원본은 질문별 기록 파일:** `records_base.jsonl`(회차 조사 원본) + `patches.jsonl`(수동 입력·회차 보정) + `daily.jsonl`(일간·주간 배치)을 `lib/build_records.py`가 검증해 `records.jsonl`을 만든다. 아티클·Diff·포털은 모두 결과물이며 언제든 다시 만든다.
- **사실만, 가설 없이:** 해석은 사실 기록 2건 이상을 근거로 연결한 것만, 전망은 회사가 공식 발표한 목표·계획만 기록한다.
- **출처 유형 분리:** 모든 지표·사건에 `claim_type`(자사 집계 / 외부 검증 / 공시)을 달고, 자사 집계는 외부 검증 출처 또는 '미확보'를 적는다.
- **공개되지 않은 값은 만들지 않는다:** 한국 가전 단독 매출·점유율·광고비 등은 기록하지 않고 질문별 `meta.json`의 `unknowns`에 남긴다.
- **통합 질문(X2~X4)은 다른 질문의 기록을 basis로 인용한다:** 사실을 복사하지 않고 `C3-E-053` 같은 번호로 연결하며, 아티클에 '다른 질문에서 인용한 기록' 칸이 생긴다.
- **본 조사는 백지에서:** 딥리서치는 이전 글을 보지 않는다. 이전 기록과의 대조는 그다음 단계에서 한다.
- **출처 등급:** A = 1차 조사·공식 발표·공시, B = 주요 언론·2차 보도, C = 블로그·출처 불명(단독 근거 금지).

### 변경 이력(일간 Diff)

- **기준선 2026-10-21:** 16개 질문 기록 1,109건을 `state/snapshot.json`에 저장했다. 그 이전 변경은 이력에 남기지 않는다.
- **매일 쌓는다:** `python3 lib/diff_day.py`가 어제 스냅숏과 오늘 기록을 비교해 바뀐 것만 `changelog/<날짜>.json`에 추가하고 스냅숏을 갱신한다. 변경 이력 페이지(`site/dist/changes.html`)는 이 파일만 읽는다.
- **담는 것:** 신규, 갱신, 판정, 정정(누락정정·단정반증 등), 삭제. 이전 문장과 이유를 함께 둔다. 변화가 없는 날은 '변화 없음' 한 줄을 남긴다.
- **회차 재조사:** `python3 lib/diff_day.py --round X1`로 돌리면 기록별 항목 대신 "X1 회차 재조사: 기록 N건" 한 줄만 남긴다.
- **배치 입력 도구:** `python3 tools/daily.py add|revise|judge` (질문 폴더의 `daily.jsonl`에 쓰고 바로 검증, 실패 시 되돌림). 회차 build 스크립트는 `daily.jsonl`을 덮어쓰지 않는다.

## 회차 실행 흐름

1. 요청서 작성 (`request_rN.md`): 고정 질문, 조사 기간, 추적 지표, 출처 기준
2. 딥리서치 → `records_base.jsonl`에 기록 추가
3. `python3 lib/build_records.py <질문 폴더>` (규칙 검증 포함)
4. `meta.json`(한 줄 답·행·미확인 항목) 갱신
5. `python3 lib/render_article.py <질문 폴더>` → `python3 site/build_site.py` (깨진 링크 0)
6. PC·폰 폭 화면 점검 → 커밋 → 포털 게시
