# signal-report 사용 안내

## 이게 무엇인가
정해 둔 질문 20개 안팎을 주기적으로 다시 조사하고, 답을 지표·사건·해석·전망 4가지 기록으로 쌓아 아티클과 변경 이력 웹페이지까지 자동으로 만드는 운영 방식입니다. 예시는 AX Signals(https://github.com/skykelly/AXblog)와 KR Appliance Signals(https://github.com/skykelly/kr_electronics_market, 최신 구조)입니다. 이 플러그인은 같은 방식을 다른 주제(예: 한국인의 생활과 삶의 변화)에 옮기는 스킬 3개입니다.

## 시작 전에 준비할 것
1. 플러그인 설치: 전달받은 `signal-report.plugin` 파일을 Claude에서 열어 설치 버튼을 누릅니다.
2. GitHub 계정과 새 저장소 하나(공개 또는 비공개).
3. 웹 검색과 서브에이전트(조사 에이전트)가 허용된 환경.
4. 웹페이지 게시가 필요하면 Claude의 게시(Artifact) 기능이 켜진 계정. 없으면 GitHub Pages로 대신할 수 있습니다.

## 쓰는 순서

### 1단계. 프로젝트 만들기 (한 번만)
Claude에게 이렇게 말합니다.
> signal-report-setup 스킬로 "한국인의 생활과 삶의 변화와 전망" 프로젝트를 새로 만들어줘.

Claude가 먼저 묻는 것: 주제와 독자, 카테고리 수, 저장 위치, 주기. 그다음 질문 목록·판정 기준·추적 지표 표를 보여 줍니다. **여기서 꼭 직접 검토하고 승인하세요.** 이후 바꾸기 비싼 결정입니다.
승인하면 저장소 뼈대, 첫 조사(R1), 포털이 만들어지고 정기 실행이 등록됩니다.

### 2단계. 정기 운영
- 일간 배치(정기 실행): 새 사건을 찾아 질문에 배정하고, 마감된 전망을 판정하고, 그날 바뀐 것을 변경 이력에 쌓습니다.
- 주간 배치(정기 실행): 30일 안에 마감되는 전망 판정, '확인 필요' 3~5건 해소, 주간 요약.
- 딥리서치 회차(요청 시): "X1 진행해줘"처럼 한 번에 1~3개 질문. 질문당 원문 30건·기록 30건 기준.
- 검증: "C와 I 카테고리 검증 탐침 돌려줘" 식으로 범위를 정해 요청
정기 실행으로 등록해 두면 사람이 말하지 않아도 돌아갑니다.

### 3단계. 자료를 직접 넣고 싶을 때
기사, 보고서 파일, 링크, 다른 AI의 조사 결과를 채팅에 붙이고 이렇게 말합니다.
> 이 자료 반영해줘 (signal-report-intake)

Claude가 주장을 뽑아 기존 기록과 비교하고 **검토 카드**를 보여 줍니다. 승인한 항목만 반영됩니다. "바로 반영"이라고 말하면 카드를 건너뜁니다.

## 지켜야 할 규칙
- 원본은 질문별 기록 파일 하나뿐이고, 아티클과 웹페이지는 언제든 다시 만드는 결과물입니다.
- 출처는 A(공식·1차) / B(주요 언론) / C(블로그·출처 불명)로 나누고, C는 단독 근거로 쓰지 않습니다.
- 원문을 직접 열지 못한 값은 단정하지 않고 '확인 필요'로 남깁니다.
- 저장소가 공개라면 남의 글 전문이나 사내 자료를 올리지 않습니다.
- 해석·전망·판정은 딥리서치 회차에서만 바꿉니다. 일간·주간 배치는 사건·지표 추가와 마감 전망 판정만 합니다.
- 해석은 기록 2건 이상을 근거로 패턴과 차이를 씁니다. 근거 없는 추측과 회사 의도 추정은 쓰지 않습니다.
- 전망은 회사 공식 계획과 분석 전망(6~18개월, 판정 방법·예측 근거·반론 포함) 두 종류이고, 틀린 전망도 지우지 않습니다.
- 변경 이력은 기준선 이후 매일 쌓이는 파일이 원본입니다. 회차 재조사는 한 줄로만 남습니다.

## 자주 막히는 곳
- 웹 검색·읽기 승인이 계속 뜰 때: 프로젝트의 `.claude/settings.json`에 WebFetch, WebSearch, Agent 허용을 넣습니다. 새 프로젝트에는 setup이 만들어 줍니다.
- 정기 실행과 수동 작업이 같은 저장소를 고치므로, 작업 전에는 항상 최신 상태로 받아야 합니다(스킬이 안내합니다).
- 포털 게시가 "다른 세션이 더 새 버전을 올렸다"며 거부되면, 최신본 위에 변경을 합쳐서 다시 게시합니다.

## 한계
- 참조 구현(AXblog)을 읽기 전용으로 받아 복사·수정하는 방식이라 인터넷에서 GitHub에 접근할 수 있어야 합니다.
- 조사 결과는 AI가 공개 자료를 근거로 만든 것이므로, 중요한 판단 전에는 출처를 직접 확인하세요.
